**Mandatory recharts mock (put at the top of each of the three test files, above imports of the component under test):**
```ts
import { describe, expect, it, vi } from "vitest";

vi.mock("recharts", async (importOriginal) => {
  const actual = await importOriginal<typeof import("recharts")>();
  return {
    ...actual,
    ResponsiveContainer: ({ children }: { children: React.ReactNode }) => (
      <div style={{ width: 600, height: 400 }}>{children}</div>
    ),
  };
});
```
This keeps `Treemap`, `LineChart`, `AreaChart`, `Line`, `Area`, `CartesianGrid`, `YAxis`, `Tooltip` etc. as the real Recharts implementations (which render actual SVG under a fixed-size, non-percentage container), while only `ResponsiveContainer` is stubbed. Note: this mock file must have a `.tsx` extension (not `.ts`) since it contains JSX; the existing test files are already `.tsx`.

From `frontend/src/components/Heatmap.tsx`:
```tsx
interface HeatmapProps { positions: Position[]; onSelect: (ticker: string) => void; }
export function Heatmap({ positions, onSelect }: HeatmapProps)
```
Wraps in `<Panel title="Allocation">`. Filters `positions` to `quantity > 0 && current_price > 0` before building Treemap cells (`size = quantity * current_price`, `pnlPercent = unrealized_pnl_percent`). Empty filtered result renders text `"Buy a position and it appears here, sized by weight."` instead of the chart. Each rendered cell is a `<g role="listitem" aria-label="{ticker} {percent(pnlPercent)}">` (from `HeatmapCell`) with an `onClick` calling `onSelect(name)` — but note `HeatmapCell` only renders its label text (`showLabel`) when `width > 44 && height > 26`, which depends on Recharts' internal Treemap layout algorithm given the mocked 600x400 container; assert on `role="listitem"` / `aria-label` presence and the `onClick` behavior via `fireEvent.click` on the `<g>` element (userEvent's `.click()` requires pointer-events which SVG `<g>` may not report consistently in jsdom — prefer `fireEvent.click` from `@testing-library/react` for this one interaction), not on the inner `<text>` labels which may be conditionally absent.

From `frontend/src/components/PnlChart.tsx`:
```tsx
interface PnlChartProps { snapshots: Snapshot[]; }
export function PnlChart({ snapshots }: PnlChartProps)
```
Wraps in `<Panel title="Portfolio Value">`. With `snapshots.length < 2`: renders text `"Snapshots are recorded every 30 seconds and after each trade."` instead of the chart — this branch needs no `ResponsiveContainer` mock interaction and is safe to assert directly. With `>= 2` snapshots: renders a `LineChart`; `rising = last.total_value >= first.total_value` controls the `Line`'s `stroke` (`var(--color-primary)` if rising, `var(--color-down)` if falling) — assert via `container.querySelector("path.recharts-line-curve")`'s `stroke` attribute (Recharts renders the line as an SVG `<path>` with class `recharts-line-curve`).

From `frontend/src/components/PriceChart.tsx`:
```tsx
interface PriceChartProps { ticker: string | null; points: number[]; update?: PriceUpdate; }
export function PriceChart({ ticker, points, update }: PriceChartProps)
```
Wraps in `<Panel title={ticker ? \`${ticker} · Session\` : "Session"}>`. With `points.length < 2`: renders `"Collecting ticks — the chart draws as prices stream in."` when `ticker` is set, else `"Select a ticker from the watchlist."` when `ticker` is null — both are direct text assertions, no chart rendering involved. The `aside` slot (only rendered when `update` is provided) shows `formatPrice(update.price)` (from `@/lib/format`'s `price()`, i.e. `.toFixed(2)`) and `percent(sessionChange)` where `sessionChange = ((last-first)/first)*100` computed from `points`, colored `text-up`/`text-down` based on `sessionChange >= 0` — these assertions don't require the chart to actually render, since `aside` is passed to `Panel` directly regardless of the `data.length < 2` branch.
